---
title: Generate OTP by Relation Reference
description: Send an OTP to a member using their RelationReference (CID).
openapi: "POST /lbms-ingress/member/api/Member/GenerateOTPByRelationReference"
---

## When to Use

Use this when the member's **RelationReference (CID)** is known — the preferred OTP flow. If you only know the email, use [Generate OTP](/api-reference/otp/generate-otp).

## Authorization

| Header | Value | Required |
|---|---|---|
| `Authorization` | `bearer {token}` | Yes |
| `Content-Type` | `application/json` | Yes |

## Body Parameters

| Parameter | Type | Required | Description |
|---|---|---|---|
| `UniquerefID` | string | Yes | The member's `RelationReference` (CID) |
| `SourceCode` | integer | Yes | Origin: `1`=Web, `2`=Mobile, `3`=Email, `4`=Service |
| `SourceAddress` | string | Yes | IP address of the requesting system |
| `OtpType` | string | Yes | Purpose of the OTP — see [Generate OTP](/api-reference/otp/generate-otp) for values |
| `ProgramId` | integer | Yes | Your loyalty program ID |
| `RelationType` | integer | Yes | Use `4` for customers |

## Responses

### 200 — Success

| Path | Type | Description |
|---|---|---|
| `results.IsSucessful` | boolean | `true` |
| `results.ErrorCode` | string | `000` |
| `results.ExceptionMessage` | string | `Success` |
| `results.ReturnObject` | boolean | `true` when OTP is sent |
| `results.Count` | integer | Always `0` |

Verify the OTP using [Verify OTP by Relation Reference](/api-reference/otp/verify-otp-by-relation).
