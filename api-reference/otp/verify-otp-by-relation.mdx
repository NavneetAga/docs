---
title: Verify OTP by Relation Reference
description: Validate a LOGIN OTP using the member's RelationReference.
---

## Endpoint

```
POST https://{domain}/lbms-ingress/member/api/Member/VerifyOTPByRelationReference
```

## When to Use

This is step 2 of the OTP login flow initiated by [Generate OTP by Relation Reference](/api-reference/otp/generate-otp-by-relation). Use it when `UniquerefID` is the member's **RelationReference (CID)**.

## Request

### Headers

| Header | Value | Required |
|---|---|---|
| `Authorization` | `bearer {token}` | Yes |
| `Content-Type` | `application/json` | Yes |

### Body

<ParamField body="UniquerefID" type="string" required>
  The member's `RelationReference` (CID).
</ParamField>

<ParamField body="OTP" type="integer" required>
  The OTP entered by the member.
</ParamField>

<ParamField body="DestinationAddress" type="string" required>
  IP address of the client device.
</ParamField>

<ParamField body="Destination" type="string" required>
  `Web` or `Mobile`.
</ParamField>

<ParamField body="OtpType" type="string" required>
  Must match the `OtpType` from `GenerateOTPByRelationReference` (typically `LOGIN`).
</ParamField>

<ParamField body="ProgramId" type="integer" required>
  Your loyalty program ID.
</ParamField>

<ParamField body="RelationType" type="integer" required>
  Use `4` for customers.
</ParamField>

### Example Request

<CodeGroup>

```bash cURL
curl --request POST \
  --url 'https://{domain}/lbms-ingress/member/api/Member/VerifyOTPByRelationReference' \
  --header 'Authorization: bearer {token}' \
  --header 'Content-Type: application/json' \
  --data '{
    "UniquerefID": "jane.doe@example.com",
    "OTP": 123456,
    "DestinationAddress": "192.168.1.1",
    "Destination": "Web",
    "OtpType": "LOGIN",
    "ProgramId": 19,
    "RelationType": 4
  }'
```

</CodeGroup>

## Response

### 200 — Success

```json
{
  "results": {
    "IsSucessful": true,
    "ErrorCode": "000",
    "ExceptionMessage": "Success",
    "ReturnObject": true
  }
}
```
