---
title: Insert Transaction V2 (Batch)
description: Submit one or more transactions asynchronously for bulk processing.
openapi: "POST /lbms-ingress/transaction-lm/API/Transaction/InsertTransactionDataV2"
---

Accepts an array of loyalty transactions and queues them for asynchronous processing by the Rule Engine. The API returns immediately with a `batch_id` — processing happens in the background. This is the recommended approach for end-of-day batch uploads, POS system syncs, or any integration where you're submitting multiple transactions at once. Use the `_xoxo_api_client_idempotency` field on each transaction to safely retry failed submissions without duplicating points.

## Authorization

| Header | Value | Required |
|---|---|---|
| `Authorization` | `bearer {token}` | Yes |
| `Content-Type` | `application/json` | Yes |

## Query Parameters

| Parameter | Type | Required | Description |
|---|---|---|---|
| `pintProgramId` | integer | Yes | Your loyalty program ID |

## Body Parameters

The request body is a **JSON array** of transaction objects.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `transaction_id` | string | No | Your transaction identifier |
| `_xoxo_api_client_idempotency` | string | Recommended | Idempotency key. Reuse on retry; new value for a genuinely new submission. See [Idempotency](/concepts/idempotency). |
| `amount` | number | Yes | Transaction amount |
| `transaction_date` | string | Yes | Date in `YYYY-MM-DD` format |
| `product_code` | string | Yes | Product identifier as configured in your program |
| `member_relation_reference` | string | Yes | The member's `RelationReference` |
| `transaction_type` | string | Yes | `dr` or `cr` as defined for your program |
| `sub_product_code` | string | No | Sub-product or SKU code |

## Responses

<AccordionGroup>
  <Accordion title="202 — Accepted">
    | Path | Type | Description |
    |---|---|---|
    | `results.IsSucessful` | boolean | `true` |
    | `results.ErrorCode` | string | `000` |
    | `results.ExceptionMessage` | string | `Success` |
    | `results.ReturnObject.batch_id` | string (UUID) | Identifies this batch. Pass to [Poll Batch Status](/api-reference/transactions/poll-batch-status). |
    | `results.ReturnObject.message` | string | `Transactions queued successfully` |
    | `results.ReturnObject.total_transactions` | integer | Number of transactions accepted |
  </Accordion>
</AccordionGroup>

## What Happens Next

<Steps>
  <Step title="Store the batch_id">
    Save `ReturnObject.batch_id` in your system.
  </Step>
  <Step title="Poll for completion">
    Call [Poll Batch Status](/api-reference/transactions/poll-batch-status) until `summary.pending === 0`.
  </Step>
  <Step title="Handle per-item outcomes">
    Each item resolves to `SUCCESS`, `FAILED`, `ON HOLD`, `PARTIAL HOLD`, or `PENDING`.
  </Step>
</Steps>
