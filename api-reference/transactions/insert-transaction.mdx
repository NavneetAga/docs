---
title: Insert Transaction
description: Submit a synchronous loyalty transaction for a member.
openapi: "POST /lbms-ingress/transaction-lm/API/Transaction/InsertTransactionData"
---

## When to Use

Use for **synchronous** single-transaction submission — processed immediately by the Rule Engine. For bulk/async use [Insert Transaction V2](/api-reference/transactions/insert-transaction-v2).

## Authorization

| Header | Value | Required |
|---|---|---|
| `Authorization` | `bearer {token}` | Yes |
| `Content-Type` | `application/json` | Yes |

## Query Parameters

| Parameter | Type | Required | Description |
|---|---|---|---|
| `pintProgramId` | integer | Yes | Your loyalty program ID |

## Body Parameters

| Parameter | Type | Required | Description |
|---|---|---|---|
| `transaction_id` | string | Yes | Your unique transaction reference |
| `amount` | number | Yes | Transaction amount |
| `transaction_date` | string | Yes | Date in `YYYY-MM-DD` format |
| `product_code` | string | Yes | Product or merchant code as configured in your program |
| `member_relation_reference` | string | Yes | The member's `RelationReference` |
| `transaction_type` | string | Yes | `DR` for debit (purchase/earn), `CR` for credit (reversal) |
| `sub_product_code` | string | No | Sub-product or SKU code |

<Note>
  Field names, `product_code`, and `transaction_type` values are enforced per your program's event template. Custom attributes must be created in Loyalife Admin before use.
</Note>

## Responses

### 200 — Success

| Path | Type | Description |
|---|---|---|
| `results.IsSucessful` | boolean | `true` |
| `results.ErrorCode` | string | `000` |
| `results.ExceptionMessage` | string | `Success` |
| `results.ReturnObject` | boolean | `true` on successful submission |

### 400 — Invalid Request

| Path | Type | Description |
|---|---|---|
| `results.IsSucessful` | boolean | `false` |
| `results.ErrorCode` | string | `E400` |
| `results.ExceptionMessage` | string | e.g. `Invalid product code` |
